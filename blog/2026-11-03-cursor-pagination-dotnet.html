Cursor pagination com .NET e EF Core: desempenho além do offset

Use a última chave vista para buscar a próxima página sem fazer o banco atravessar milhares de linhas descartadas.

.NETEF CorePerformance

Paginação por offset é simples: a API recebe o número da página, traduz esse número em Skip e retorna Take itens. Ela funciona bem para listas pequenas e telas que realmente precisam pular para uma página arbitrária. Em listas grandes, porém, o banco precisa localizar e descartar todas as linhas anteriores ao offset antes de devolver a página. Quanto mais profunda a página, mais trabalho pode ser feito para retornar sempre o mesmo pequeno conjunto.

O problema que o cursor resolve

Uma consulta como Skip(100_000).Take(20) não transfere necessariamente 100 mil registros para a aplicação, mas pode obrigar o banco a percorrê-los ou ordená-los antes de ignorá-los. Além da latência crescente, inserções e exclusões entre duas requisições podem deslocar o offset e causar duplicações ou lacunas. Cursor pagination, também chamada de keyset pagination, começa da última chave recebida: em vez de pedir “página 5.001”, a cliente pede “os próximos itens depois deste ponto”.

Aplique-a em feeds cronológicos, auditorias, mensagens, eventos e APIs com navegação sequencial de “carregar mais”. Mantenha offset quando o produto exige ir diretamente para qualquer número de página, mostrar um total exato ou trabalhar com um conjunto pequeno e estável. Cursor não é uma substituição automática: ele troca salto arbitrário por uma busca incremental muito mais eficiente quando há um índice compatível.

1. Escolha uma ordenação estável e crie o índice

A coluna de ordenação deve ser determinística. Uma data sozinha pode empatar; por isso, o exemplo usa CreatedAt em ordem decrescente e Id como desempate. O predicado e o índice precisam refletir a mesma ordem. Ajuste o nome da tabela e do índice às convenções do seu projeto.

public sealed class Activity
{
    public long Id { get; set; }
    public DateTimeOffset CreatedAt { get; set; }
    public string Message { get; set; } = "";
}

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Activity>()
        .HasIndex(activity => new { activity.CreatedAt, activity.Id });
}

2. Defina um cursor opaco e o contrato da resposta

O cliente não precisa conhecer os detalhes da consulta. Retorne um token opaco que contenha a posição da última linha entregue e aceite-o de volta como after. Base64url evita caracteres que exigem escape na query string; a validação devolve um erro explícito para tokens inválidos, em vez de tratá-los silenciosamente como a primeira página.

using System.Text;
using System.Text.Json;

public sealed record ActivityCursor(DateTimeOffset CreatedAt, long Id);
public sealed record ActivityItem(long Id, DateTimeOffset CreatedAt, string Message);
public sealed record ActivityPage(IReadOnlyList<ActivityItem> Items, string? NextCursor);

static string EncodeCursor(ActivityCursor cursor) =>
    Convert.ToBase64String(Encoding.UTF8.GetBytes(JsonSerializer.Serialize(cursor)))
        .TrimEnd('=').Replace('+', '-').Replace('/', '_');

static bool TryDecodeCursor(string value, out ActivityCursor? cursor)
{
    cursor = null;
    try
    {
        var base64 = value.Replace('-', '+').Replace('_', '/');
        base64 = base64.PadRight(base64.Length + (4 - base64.Length % 4) % 4, '=');
        cursor = JsonSerializer.Deserialize<ActivityCursor>(
            Encoding.UTF8.GetString(Convert.FromBase64String(base64)));
        return cursor is not null;
    }
    catch (FormatException) { return false; }
    catch (JsonException) { return false; }
}

3. Busque depois da última chave, não depois de um número de linhas

O filtro reproduz a ordenação. Para CreatedAt DESC e Id DESC, uma linha posterior tem uma data menor ou a mesma data com Id menor. Solicitar um item extra permite saber se existe outra página sem executar COUNT. Faça a projeção e AsNoTracking antes da materialização para manter a leitura enxuta.

app.MapGet("/activities", async (
    string? after,
    int? pageSize,
    AppDbContext db,
    CancellationToken cancellationToken) =>
{
    const int defaultPageSize = 20;
    const int maximumPageSize = 100;
    var size = Math.Clamp(pageSize ?? defaultPageSize, 1, maximumPageSize);

    ActivityCursor? cursor = null;
    if (!string.IsNullOrWhiteSpace(after) && !TryDecodeCursor(after, out cursor))
        return Results.BadRequest(new { error = "The cursor is invalid." });

    var query = db.Activities.AsNoTracking()
        .OrderByDescending(activity => activity.CreatedAt)
        .ThenByDescending(activity => activity.Id);

    if (cursor is not null)
    {
        query = query.Where(activity =>
            activity.CreatedAt < cursor.CreatedAt ||
            (activity.CreatedAt == cursor.CreatedAt && activity.Id < cursor.Id))
            .OrderByDescending(activity => activity.CreatedAt)
            .ThenByDescending(activity => activity.Id);
    }

    var rows = await query
        .Select(activity => new ActivityItem(activity.Id, activity.CreatedAt, activity.Message))
        .Take(size + 1)
        .ToListAsync(cancellationToken);

    var hasNextPage = rows.Count > size;
    var items = rows.Take(size).ToList();
    var nextCursor = hasNextPage
        ? EncodeCursor(new ActivityCursor(items[^1].CreatedAt, items[^1].Id))
        : null;

    return Results.Ok(new ActivityPage(items, nextCursor));
});

4. Consuma a próxima página

A primeira chamada não envia after. Nas chamadas seguintes, a aplicação usa NextCursor retornado pela API. O cursor pertence à mesma ordenação e aos mesmos filtros da consulta; se filtros como tenant, status ou busca mudarem, descarte-o e comece outra sequência. Para impedir que um token seja reutilizado em outro contexto, inclua e valide esses valores no payload ou assine-o no servidor.

5. Valide o plano e defina a semântica de mudanças

Índice, ordenação e predicado devem caminhar juntos; confirme isso no plano de execução e com uma base representativa. A técnica evita percorrer offsets profundos, mas não congela o conjunto: um item novo antes do cursor normalmente aparecerá em uma atualização futura, não na sequência atual. Se a regra de negócio exige um retrato imutável, defina um limite temporal, use versionamento ou uma transação adequada ao banco. Para navegar para trás, gere um cursor de início e inverta o predicado e a ordem, depois reverta os itens antes de responder.

Cursor pagination resolve uma limitação concreta do offset: buscar a próxima página não deve ficar mais cara apenas porque a pessoa já percorreu muitas páginas. Com uma ordenação única, um índice correspondente, cursor validado e um contrato claro de próxima página, EF Core traduz a intenção para uma consulta que o banco pode continuar a partir da última chave conhecida.
