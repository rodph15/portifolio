Full-text search com .NET e EF Core: PostgreSQL e SQL Server

Construa uma busca textual rápida e relevante: veja quando sair do LIKE, crie índices e conecte PostgreSQL ou SQL Server a uma aplicação ASP.NET Core com EF Core.

.NETEF CoreBancos de dados

Uma busca por título ou conteúdo costuma começar com Contains no LINQ, traduzido em muitos provedores para LIKE '%termo%'. É uma escolha honesta para poucos registros e um filtro simples. Quando a busca vira uma funcionalidade do produto, porém, full-text search (FTS) oferece outra estrutura: tokenização por idioma, normalização linguística, operadores de consulta, ranking e índices invertidos.

Por que não depender apenas de LIKE?

Com o curinga inicial, o otimizador normalmente não pode usar um índice B-tree convencional para localizar o prefixo; pode precisar examinar muitas linhas e comparar texto. LIKE também não sabe que “configuração” e “configurações” são formas próximas, não ordena por relevância e não fornece uma sintaxe própria para combinar termos. FTS indexa termos para encontrar documentos candidatos e calcula relevância; ainda assim, não substitui busca por identificador, igualdade, prefixos específicos ou filtros estruturados.

1. Modele o documento pesquisável

O exemplo usa artigos com título e corpo. Mantenha autorização, filtros de publicação e paginação na consulta final: um índice de texto acelera a localização, mas não aplica as regras do seu domínio.

public sealed class Article
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public string Body { get; set; } = "";
    public bool IsPublished { get; set; }
}

2. Instale e registre o provedor do EF Core

Use um provedor por aplicação. As APIs de FTS abaixo são específicas do banco; mantê-las em uma implementação de busca própria evita fingir que PostgreSQL e SQL Server têm a mesma sintaxe ou o mesmo comportamento.

# PostgreSQL
dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL

# SQL Server
dotnet add package Microsoft.EntityFrameworkCore.SqlServer

# Ferramentas de migration (se ainda não existirem)
dotnet add package Microsoft.EntityFrameworkCore.Design
dotnet tool install --global dotnet-ef
var connectionString = builder.Configuration.GetConnectionString("BlogDatabase")
    ?? throw new InvalidOperationException("Connection string 'BlogDatabase' not found.");

// Escolha somente uma das linhas conforme o banco usado.
builder.Services.AddDbContext<BlogDbContext>(options =>
    options.UseNpgsql(connectionString));

3. PostgreSQL: vetor gerado e índice GIN

No PostgreSQL, crie um tsvector gerado a partir das colunas pesquisáveis e um índice GIN sobre ele. A configuração de texto portuguese remove stop words e reduz palavras às suas raízes para português; escolha a configuração que corresponde ao conteúdo predominante e valide seus resultados com dados reais.

using NpgsqlTypes;

public sealed class Article
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public string Body { get; set; } = "";
    public bool IsPublished { get; set; }
    public NpgsqlTsVector SearchVector { get; private set; } = null!;
}

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Article>()
        .HasGeneratedTsVectorColumn(
            article => article.SearchVector,
            "portuguese",
            article => new { article.Title, article.Body })
        .HasIndex(article => article.SearchVector)
        .HasMethod("GIN");
}

Crie e aplique a migration. Ela registra a coluna gerada e o índice na mesma evolução de esquema que o restante do modelo.

dotnet ef migrations add AddPostgresFullTextSearch
dotnet ef database update

A consulta usa a coluna indexada e WebSearchToTsQuery, que aceita uma sintaxe de pesquisa mais amigável. O termo entra como parâmetro do provider; não monte SQL concatenando a entrada da pessoa usuária.

var term = request.Term?.Trim();
if (string.IsNullOrWhiteSpace(term)) return Results.BadRequest("Search term is required.");

var query = EF.Functions.WebSearchToTsQuery("portuguese", term);
var results = await db.Articles.AsNoTracking()
    .Where(article => article.IsPublished)
    .Where(article => article.SearchVector.Matches(query))
    .OrderByDescending(article => article.SearchVector.Rank(query))
    .Select(article => new { article.Id, article.Title })
    .Take(20)
    .ToListAsync(cancellationToken);

return Results.Ok(results);

4. SQL Server: catálogo e índice full-text

No SQL Server, o catálogo e o índice full-text são objetos distintos. O índice precisa de uma chave única, não nula e de uma coluna; neste modelo, a chave primária criada pelo EF Core é PK_Articles. Ajuste o nome se sua migration usar outra convenção e confira se o componente Full-Text and Semantic Extractions for Search está disponível na instância.

protected override void Up(MigrationBuilder migrationBuilder)
{
    migrationBuilder.Sql("""
        CREATE FULLTEXT CATALOG BlogSearchCatalog AS DEFAULT;

        CREATE FULLTEXT INDEX ON dbo.Articles
        (
            Title LANGUAGE 1046,
            Body LANGUAGE 1046
        )
        KEY INDEX PK_Articles
        WITH CHANGE_TRACKING AUTO;
        """);
}

protected override void Down(MigrationBuilder migrationBuilder)
{
    migrationBuilder.Sql("""
        DROP FULLTEXT INDEX ON dbo.Articles;
        DROP FULLTEXT CATALOG BlogSearchCatalog;
        """);
}

O EF Core não traduz uma expressão LINQ genérica para CONTAINSTABLE. Use uma consulta SQL parametrizada e mantenha a projeção no banco. A pessoa usuária pode informar uma condição FTS válida, por exemplo "entity framework" ou "entity*"; se a interface oferecer operadores, documente-os e valide a experiência esperada.

var term = request.Term?.Trim();
if (string.IsNullOrWhiteSpace(term)) return Results.BadRequest("Search term is required.");

var results = await db.Articles.FromSqlInterpolated($"""
    SELECT article.*
    FROM dbo.Articles AS article
    INNER JOIN CONTAINSTABLE(dbo.Articles, (Title, Body), {term}) AS search
        ON article.Id = search.[KEY]
    WHERE article.IsPublished = CAST(1 AS bit)
    ORDER BY search.RANK DESC
    """)
    .AsNoTracking()
    .Select(article => new { article.Id, article.Title })
    .Take(20)
    .ToListAsync(cancellationToken);

return Results.Ok(results);

5. Meça, trate limites e evolua a experiência

Compare o plano de execução e a latência com termos frequentes e raros, usando uma base representativa. Aplique um limite de resultados, ordene por ranking antes de paginar e combine FTS com filtros seletivos, como idioma ou publicação. Destaques, sinônimos, correção ortográfica e autocomplete são capacidades adicionais, não efeitos automáticos do índice. Para autocomplete no meio da palavra, avalie recursos específicos do banco ou um mecanismo dedicado.

A mudança essencial é tratar a busca como uma consulta linguística indexada, e não como uma comparação de substring. Com uma coluna ou índice de texto, uma consulta parametrizada e métricas de produção, a aplicação ganha relevância e escala sem perder as regras de acesso e publicação que tornam os resultados corretos.
